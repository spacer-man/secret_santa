# Тайный Санта — контекст проекта для Claude

Читай это перед работой. Здесь всё, о чём договорились с владельцем (общение на русском,
владелец сидит с телефона: отвечать коротко, результат первым, скриншоты прикладывать путями).

## Что это

Новогодний «Тайный Санта» со всего мира. Каждый участник пишет поздравление незнакомцу;
ровно в 00:00 по своему часовому поясу каждый получает анонимное поздравление от случайного
участника и может ответить реакцией / анонимным ответом. Прошлый сезон: Telegram-бот, 11 участников.
Цель сезона: больше участников и «вау»-атмосфера. Бюджет: только VPS + домен.

## Архитектура (рабочая ветка `claude/secret-santa-multiplatform-bnfqt3`)

- `bot/` — Python 3.13, aiogram 3 (бот) + FastAPI (API) из одного образа.
  - `src/main.py` — бот: вебхук (aiohttp, `/telegram/webhook`, порт 8080) если задан `WEBHOOK_URL`,
    иначе polling (локальная разработка). Ставит кнопку меню на Mini App (`WEBAPP_URL`).
  - `src/api_main.py`, `src/api/` — API `/api/*` (порт 8000). Авторизация: `Authorization: tma <initData>`
    (Mini App, HMAC по токену бота) или `Bearer <token>` (сайт, Telegram Login Widget → наш подписанный токен).
    Медиа отдаются по подписанным URL с поддержкой Range.
  - `src/timezones.py` — пояса в формате `UTC+3`, `UTC+5:30`; есть UTC+13/+14 и получасовые.
  - `src/services/delivery.py` — модель `Delivery` (один подарок на пользователя на год), выбор поздравления
    (наименее доставленное, не своё, только этого сезона — с 1 февраля прошлого года), реакции/ответы, статистика.
  - `src/services/mailer/` — рассылка раз в минуту, идемпотентно (не пропускает пояса, не дублирует).
  - `src/services/mandarins.py` — валюта 🍊, леджер `MandarinTx` (одна награда на user/reason/ref).
  - `src/services/tree.py` — данные ёлки: шары (box/hung/lit), звезда, гирлянда, уровень праздника 1–10.
  - `src/db/core.py` — `create_all` + идемпотентные `ALTER ... IF NOT EXISTS` (миграции без alembic),
    advisory lock (бот и API стартуют одновременно).
  - Тесты: `cd bot && uv run pytest` (SQLite); на Postgres:
    `TEST_DB_URL=postgresql+asyncpg://... ` (локально был postgres 16 в `/usr/lib/postgresql/16/bin`).
- `web_app/` — Angular 21 (standalone, signals). Один фронт = Telegram Mini App + сайт + PWA.
  - Зависимости ставить **bun** (`bun install`), не npm (у npm баг с этим lock-файлом). Сборка `npx ng build`.
  - `core/` — `telegram.ts` (обёртка WebApp), `api.ts`, `store.ts` (состояние, гарды), `i18n.ts` (RU/EN), `time.ts`.
  - `pages/` — home (ёлка, отсчёт, приглашение, «новогодняя волна»), register, new-wish (с конструктором шара),
    my-wishes, inbox (реакции/анонимный ответ), login (Telegram Login Widget).
  - `components/tree3d/` — 3D-сцена (three.js, лениво грузится, без WebGL / `?scene=2d` → 2D-ёлка `components/tree/`):
    - `scene.ts` — мир: двор, постамент, забор с фонарями, домик (`cabin.ts`), лес/горы, снег, шары, гирлянда,
      звезда, паровозик (уровень ≥6), уголки с фигурами, режим «Украсить двор», камера (360°, зум, подлёт к уголку).
    - `tree-model.ts` — ель (гладкие ярусы + пушистый снег, ~24k треугольников). `treeRadius()` обязан совпадать с геометрией.
    - `models.ts` — модели **Kenney Holiday Kit (CC0)** из `public/models/holiday/` (лицензия лежит рядом), toon-материал + контур.
    - `layout.ts` — анти-пересечения: «следы» объектов из кругов (длинные модели = ряд кругов), resolve.
    - `?debug` в URL выставляет `window.santaTree` (для скриншотов).
- Локально через туннель: `./scripts/dev-tunnel.sh` (настройки `.env.dev`, см. `.env.dev.example`): cloudflared/ngrok/ssh →
  `ng serve :4200` (прокси `/api`→8000, `/telegram/webhook`→8080), бот на вебхуке, SQLite в `.dev/`; по Ctrl+C снимает вебхук и кнопку.
- Деплой: `docker-compose.yaml` (db, state_storage, bot, api, web=Caddy с авто-HTTPS), `.env.example`,
  инструкция `docs/DEPLOY.md`. PWA: `public/manifest.webmanifest`, `public/sw.js`, иконки.

## Принятые решения

- Мобильные приложения = **PWA** (без App Store/Google Play). Позже можно TWA в Google Play ($25).
- Caddy вместо nginx+certbot. Вебхук вместо polling на проде.
- Анимации/вид в стиле «уюта» как в новогоднем событии World of Tanks (механики, а не их арт).
- 3D: three.js, мультяшный cel/toon shading с контуром (outline). Облако точек / Gaussian splatting — нет.
- Модели: Kenney (CC0). Unity Asset Store — нет (лицензия). Всё, что берём, — только CC0/проверенная лицензия.
- Пакет для окружения: создано облачное окружение `secret_santa` с доступом к kenney.nl.

## Игровая механика (сделано)

- Каждое поздравление = шар на ёлке пользователя: 🎁 коробка под ёлкой (на модерации) → висит (одобрено)
  → **горит** (дошло до получателя в НГ). Цвет (8) и узор (6) выбираются при написании.
- Звезда горит после открытия своего подарка; гирлянда — огоньки за приглашённых друзей.
- Уровень праздника 1–10 меняет сцену: ≥3 фонари/окна, ≥5 гирлянда на заборе, ≥6 паровозик, ≥9 северное сияние.
- Мандаринки 🍊 (только за действия, не продаются): одобрено +30, дошло +20, реакция +5, ответ +10,
  друг пришёл +15, друг написал одобренное +50, открыл подарок +50.
- Рефералы: `t.me/<bot>?start=r_<uuid hex>`, на сайте `?ref=`.
- Двор: 5 уголков у забора («у крыльца», «у фонаря», «снежная горка», «у камней», «у тропинки»), в каждом
  горка подарков, вокруг места под фигуры. Правила стойки по типу: персонажи смотрят на ёлку, сани боком,
  трости/фонари как угодно; выбирается поза с минимальным сдвигом; без пересечений.
- Режим «Украсить двор»: издалека большая голубая стрелка над горой → подлёт камеры к уголку → маленькие
  стрелки над местами; если выбрана фигура — полупрозрачное (70%) голубое превью. Подсказка зависит от вида.
- Пустое место под новый шар медленно «дышит» и светится.
- Рельеф (`components/tree3d/terrain.ts`): неровная снежная поверхность с сугробами и контуром (outline по гребням);
  ровно на площади, у домика и на тропинке. Объекты на снегу берут высоту из `terrainHeight()`.
- Гирлянда-бахрома под крышей домика (`cabin-lights.ts`): скины разноцветная/тёплая белая/золотая/ледяная/леденец
  со своей анимацией; нажатие на домик → камера к домику + компактная полоска выбора, закрытые скины можно примерить.
  `skins.ts` без three.js — UI импортирует только его (иначе three.js попадает в основной бандл).
- Погода: ясно (звёздное небо, бесплатно) / лёгкий снег (бесплатно) / снегопад (150 🍊) / метель (400 🍊) — кнопка ❄️ на сцене; плотные режимы
  покупаются в лавке (см. «Лавка»).
- Северное сияние (уровень ≥9): отдельные колышущиеся ленты над лесом; видно только в ясную/слабоснежную погоду.
- Шары висят на нитях с кончиков веток нижнего края ярусов (кроме самого нижнего), нить отклоняется от веток.
- Снег (`tree3d/snow.ts`): свой мягкий toon-градиент + холодный «пушистый» ободок (`snowMaterial`), искры-блёстки
  (`buildGlitter`: земля, постамент, ёлка, крыша; мерцают от времени и поворота камеры). Весь снег красить через `snowMat()`.
  Снег на крыше домика — одна гладкая поверхность через конёк (`roofSnowGeometry` в cabin.ts): высота = функция (x, z),
  кромка заворачивается и уходит внутрь кровли (без зазора и самопересечений). Коробкой больше не делать.
- Живость (`tree3d/life.ts`): снегири на столбах забора (прыгают, клюют, перелетают), падающие звёзды в ясную погоду,
  следы от крыльца к калитке; фигуры во дворе шевелятся (`idle()` в scene.ts), огонь фонарей/окон мерцает, дым паровозика шлейфом.
- Фонарь — один ассет (`tree3d/lantern.ts`, `lanternFactory`): столбы забора и крыльцо ставят его через `build(scale)`,
  включение/выключение всех разом — `setOn()`. Новые фонари добавлять только так, не собирать из боксов на месте.
- Свет фонарей — настоящий (`PointLight` в каждом фонаре, `LANTERN_LIGHT` в lantern.ts): падает на снег и предметы вокруг,
  мерцает вместе с огнём; спрайт остаётся только маленьким ореолом пламени. На слабых устройствах (`realLightsWanted()` в
  scene.ts: <6 ядер или <4 ГБ) — прежний большой спрайт-ореол без источников света; принудительно `?light=real|simple`.
  Свет фонаря падает только на грани, повёрнутые к нему (колпак сверху и снежная шапка остаются тёмными): toon-затенение
  даёт отвёрнутым граням самую тёмную полосу, поэтому `facingLights()` правит чанк three.js для источников с
  `decay == FACING_DECAY`; свет внутри ёлки (`treeLight`) оставлен как был. Теней (заслонения предметами) нет.
  Окна домика (кроме заднего) в «настоящем» режиме светят `SpotLight`-конусом наружу и вниз на снег (`WINDOW_LIGHT`,
  `windowSpots` в cabin.ts), спрайт-«лужа» света тогда скрыт. Гирлянда домика светит одним общим `PointLight` (был и раньше).
  Гирлянда на заборе, шары, звезда — только светящийся материал, вокруг не светят.
- Свечение в «настоящем» режиме — **bloom** (штатная постобработка three.js: `EffectComposer` + `UnrealBloomPass` в scene.ts),
  самодельного свечения нет. Светится всё, что ярче белого (порог 1.0): источники красятся через `emit(color, power)` из
  glow.ts (`BLOOM_POWER`) — стекло фонарей, звезда, горящие шары, гирлянды ёлки/забора/домика, окна; стекло фигуры-фонаря
  выделяется по цвету текселя (`lampGlass`). Ореолы источников делать через `this.halo()` — в «настоящем» режиме он скрыт,
  в простом это прежний спрайт; `this.glow()` — для того, что должно остаться спрайтом всегда (луна, стрелки, подсказки).
  Кадр при bloom рисуется в линейный буфер: свои шейдеры, пишущие «экранные» цвета, обязаны заканчиваться
  `gl_FragColor = sRGBTransferEOTF(gl_FragColor); #include <colorspace_fragment>` — иначе всё светлеет.
  Интерфейс фонаря: `Lantern.shine(k)`.
- Ореолы-спрайты (`glow.ts`, `pushForward`): глубина проверяется ближе к камере, чем сам спрайт, — модели, вокруг которых
  он светится, его не «режут», а всё, что реально спереди, по-прежнему заслоняет. Новые ореолы делать через `this.glow()`.
  Фигура-фонарь из лавки горит всегда (`lightFigureLantern`), её источник (`figureLight`) создан заранее — добавление
  источников на лету пересобирает шейдеры.
- Снежные шапки (столбы, труба, фонарь) — замкнутые формы: кромка заворачивается и уходит в опору, без «среза» снизу.
- Северное сияние рисуется шейдером (лучи разной ширины и высоты, зелёный низ → розовый → фиолетовый), не текстурой.
- Места под шары: все ярусы кроме нижнего, шаг ~0.62; порядок заполнения — «самое дальнее от занятых», чтобы любое
  число шаров ложилось равномерно по всей ёлке.
- Блеск снега — в самом материале (`snowMaterial`, шейдер): кристаллики по мировой сетке, каждый вспыхивает, только когда
  «смотрит» на камеру, поэтому блики меняются при вращении; сила/плотность — константы `SPARKLE_*`. Крупные звёздочки
  (`buildGlitter`) оставлены как редкий акцент.
- Снежинки: атлас 2×2 (мягкая + три шестилучевых кристалла), вращаются в шейдере; каждая третья — крупный кристалл.
- Дым (труба, паровозик) — объёмные cel-клубы с контуром (`buildPuff`/`puffScale` в life.ts), не размытые спрайты.
- Горы: один low-poly меш со снежными шапками, без тумана (цвета уже ночные).
- Контур (outline.ts): экранной толщины, у забора, домика, моделей Kenney и леса (instanced). Ночь затемнена для контраста со светящимся.

## Интерфейс: «бумажный табель» (сделано, первая версия)

- Образец стиля — печатный табель-календарь (референс владельца: календарь «Мира танков»; берём приёмы, не их арт):
  лист фактурной бумаги на фоне «стена + крашеная полоса», тонкие линейки, цифры и заголовки с засечками
  (Roboto Slab, пакет `@fontsource-variable/roboto-slab`, шрифт раздаём сами), красные рамки-штампы, 3D-сцена — «иллюстрация» листа.
- Две темы: светлая бумага и тёмная («тот же лист ночью»). Токены в начале `styles.scss` (`--paper*`, `--ink*`, `--rule*`,
  `--stamp`, `--orange`, `--rarity-*`), тёмные — `:root[data-theme='dark']`. `core/theme.ts`: авто (Telegram `colorScheme` /
  система) → светлая → тёмная, выбор в `localStorage['santa.theme']`, кнопка в «выходных данных» внизу листа.
  Цвета в компонентах — только токенами, без «зашитых» hex (иначе ломается одна из тем).
- «Человечность» — рамки, линейки, штампы и кляксы не CSS-прямоугольники, а штрихи «от руки»: `core/handmade.ts` находит
  элементы по селекторам из `RULES` и кладёт в каждый SVG-слой `svg.hm` (текст не трогается). Приёмы (подсмотрены в
  открытых наборах для рисованной анимации кодом): точки пути дрожат и сглаживаются кривой; **карандаш** — три прохода
  (основной и два лёгких рядом), нажим меняется по длине (линия то тёмная, то еле видна, местами рвётся), концы сужаются;
  рамка = четыре отдельных штриха с перелётом за углы; заливка — три неровных слоя со сдвигом и тёмной кромкой; зерно
  грифеля — см. ниже. Случайность задаётся
  зерном элемента: перерисовка при изменении размера даёт тот же рисунок. «Кипение» (4 варианта по кругу, 6 кадров/с) — только
  у печати и главной кнопки (`BOILING`), выключается при «меньше движения». Цвет рисунка — CSS-переменная `--hm`.
  Новый рисованный элемент = строка в `RULES` + цвет в styles.scss; CSS-рамку/фон у него убрать. Рамка сцены `hm-picture` — без зерна. Листки отсчёта и цифры слегка повёрнуты по-разному.
- Заливки (решено с владельцем): **большие площади** (рамка-штамп с отсчётом и подобные) — акварель (`paint()`);
  **остальное** (кнопки, пятна под значками) — карандашная штриховка широкой линией (`hatch()`): штрихи одного
  направления, угол каждого гуляет на пару градусов («в пределах человечности»), разный нажим, неровные концы, редкие
  пропуски; у кнопок бледная основа + два прохода + тёмный контур. Перекрёстная штриховка — только под фигурами в лавке.
  Кнопки с ценой — еловый зелёный `--buy` (🍊 не сливается).
- Зерно карандаша — не SVG-фильтр, а тайловая CSS-маска, которую handmade.ts делает один раз (`--hm-grain` сильное для
  линий, `--hm-grain-soft` слабое для штриховки: текст на кнопке должен читаться). Фильтры на каждый слой тормозили панели.
  Слой `svg.hm` больше элемента на `PAD` = 14 px со всех сторон (в CSS `left/top: -14px`) — иначе маска обрезает перелёты.
- Отклик кнопок (`BUTTONS` в handmade.ts): наведение мышью — «кипящая» кнопка замирает, обычная один раз перерисовывается,
  обе становятся ярче (`.hm-hover`); нажатие — рисунок «растекается» (крупнее и жирнее, `press` в `draw()`) и чуть темнеет
  (`.hm-press`). На тач-устройствах наведения нет, работает только нажатие.
  Плюс **обводка**: при наведении/нажатии кнопка небрежно обводится толстым мягким карандашом одной линией «без отрыва
  от бумаги» (`scribble()`: полтора с лишним витка, каждый виток смещён и шире предыдущего). Форма повторяет кнопку:
  скруглённый прямоугольник, у круглых кнопок — кольцо. Линия режется на полупрозрачные куски с плоскими концами
  (общая точка на стыке): где карандаш прошёл дважды — тон темнее. Анимация прорисовки кусок за куском (`SCRIBBLE_MS`);
  пока кнопка нажата — обводка остаётся. Отдельный слой `svg.hm-outline`; над сценой — белая. Толщина до 8 px,
  у маленьких кнопок тоньше (иначе кольцо сливается в пятно).
  После отпускания кнопки обводка уходит так же, как пришла, — начало линии исчезает первым (`hm-leaving`,
  `hm-unscribble`), и не возвращается, пока курсор не уйдёт и не придёт снова (`spent`).
- Штриховка — одна непрерывная линия-зигзаг «туда-обратно» (у перекрёстной — по одной линии на направление), порезанная
  на куски по `HATCH_PIECE` штрихов со своим нажимом. Развороты у края — плавные петли (кривая за край и обратно),
  без острых углов: острые стыки давали «заломы». Кусок заканчивается в начале следующего штриха, поэтому швов нет. При перерисовке от взаимодействия (наведение — 420 мс, нажатие и
  отпускание — 200 мс) штриховка прорисовывается кусок за куском (`.hm-seq`, `--i`, `--each`), а старый рисунок под ней
  гаснет (`.hm-old`); при обычной перерисовке (размер, первый показ) анимации нет. Варианты «кипения» лежат в `g.hm-v`.
- Кнопки поверх сцены (🍊, лавка, «Украсить двор», погода, зум) — бумажные ярлычки, наклеенные на иллюстрацию
  (`tag` / `tag-round`), чуть под разными углами.
- Стиль распространён на всё (таблица `RULES` в handmade.ts — единственное место, где элементу назначается рисунок):
  заголовки между линейками (`title`), рамка-штамп (`stamp`), заштрихованные блоки — главная кнопка, цены, активная
  вкладка лавки, тост (`ink-block`); рамочные вещи — кнопки, варианты выбора (погода, гирлянды, реакции, узоры шара),
  карточки и наборы лавки, переключатель темы (`card`; выбранный вариант обведён красным карандашом, класс `selected`);
  тихие кнопки одной лёгкой линией (`light`); подчёркивания цифр и активной вкладки (`underline`), линейки строк и
  подзаголовков панелей (`rule`); полосы прогресса — карандашная линия и заштрихованная часть (`bar-track`/`bar-fill`);
  цитаты, подсказки, конструктор шара, «моя» строка волны — акварельное пятно (`note`); бейджи и чипы — лёгкая
  штриховка (`chip`); поля ввода — рамка поверх поля соседним элементом (`field`, внутрь `<select>/<textarea>` не вставить).
  Виды из `BARE` получают класс `hm-bare`: CSS-фон и рамка выключаются. Перерисовка следит за классами из `STATES`.
- Просмотрены глазами в обеих темах: главная, кошелёк, погода, гирлянды, звезда, лавка (фигуры, наборы, погода),
  «написать», «мои», «подарки», регистрация. Не смотрел: вход (виджет Telegram), панель шара, панель места во дворе,
  2D-режим, английский язык.

## Маскот, правила, установка, иней (сделано)

- **Маскот** (`core/mascot.ts`, `core/mascot-lines.ts`, `components/mascot/`): Дед Мороз или Санта (рисунок SVG
  `mascot-art`) и характер: классический / весельчак (сленг и
  приколы для подростков) / сказочник / ворчун. Внешность по характеру: очки, пенсне, нахмуренные брови. Выбор — в
  `localStorage['santa.mascot']` (только этот браузер; по умолчанию RU → Дед Мороз, EN → Санта). `<mascot-says topic>`:
  облачко с репликой, тап по облачку — следующая реплика темы `more` (по умолчанию советы), тап по фигуре — окно выбора.
  Реплики: язык → характер → тема (`greet`, `tip`, `rules`, `teaser`, `install`, `write`, `gift`, `midnight`),
  токены `{me}`, `{laugh}`, `{name}`; в русских репликах нет глаголов с родом про читающего. Стоит на главной (новичку —
  `teaser` + кнопка «Как играть», в полночь — `gift`), на «Как играть», «Написать», в карточке установки.
  Живость (`mascot-art.ts` + анимации `mascot-*` в styles.scss): всегда дышит, качает головой, оглядывается, моргает,
  кончик шапки Санты качается, снежинка на шапке Мороза мерцает; пока «печатает» реплику — кивает, брови вверх, смотрит
  на облачко, рот двигается. Раз в 8–20 с — действие своего характера (`ACTS`: машет варежкой, подпрыгивает, кивает,
  оглядывается, блик очков, вздох с закрытыми глазами, мотает головой); при появлении машет (`hello`), при смене героя/
  характера подпрыгивает. Части — вложенные группы (`m-all` › `m-breath`/`m-head-act` › `m-head`), чтобы постоянные
  движения и разовые действия не перебивали друг друга. Низ халата не обрезан: халат идёт ниже, на нём штриховка,
  и всё уходит в прозрачность CSS-маской. Туловище узкое, руки висят по бокам (видны плечи) и тоже растворяются;
  обе руки одинаковые (плечо + предплечье, левая — зеркало правой); воротник — два треугольных меховых лацкана
  «галочкой» от плеч к центру, переходят в белую полосу халата, лежат под руками;
  правая — с локтем: для взмаха плечо уходит в сторону (`mascot-wave`), предплечье `m-fore` сгибается вверх и качается
  (`mascot-wave-fore`), большой палец вверх и к голове; без швов (плечи, локти): сначала халат и все части рук
  с контуром, поверх — их заливки без контура (`m-fill-only`; копии движущихся частей с тем же классом двигаются вместе);
  манжета с варежкой (`m-hand`) видны только у поднятой руки.
  При «меньше движения» всё стоит.
  Не сделано: голос маскота в сообщениях бота; тема `midnight` пока не используется.
- **Как играть** — страница `/rules` (`pages/how-to.ts`, без входа): три шага, состояния шара, мандаринки (суммы из
  `/api/config`), друзья и фигуры за 1/3/5/10 друзей, честность/анонимность. Ссылка под отсчётом на главной.
  Просмотр отмечается в `localStorage['santa.rules.seen']` (`core/onboarding.ts`).
- **Установка** (`core/install.ts`, `components/install-card.ts`): с 2-го визита; Android/десктоп — системный диалог
  (`beforeinstallprompt`), iOS Safari — шаги «Поделиться → На экран „Домой“», в Telegram — ярлык Mini App
  (`addToHomeScreen`, Bot API 8.0). «Не сейчас» прячет на 10 дней.
- **Иней на листе** (`frost()` в handmade.ts, рисуется вместе с рамкой `.page`): перистые узоры из углов и снежинки
  по краям; все иголки собраны в три `<path>` по толщине (дёшево), обрезаны по листу. Цвет — токен `--frost`.

## Известные ограничения / не проверено

- Плавность 3D на реальных (особенно слабых) телефонах не проверена — только эмуляция (SwiftShader).
- Ogg-голосовые могут не играть в iOS Safari.
- Шары из бота (не из приложения) получают случайный стабильный цвет/узор.
- Контур ёлки/домика/шаров сделан другим способом, чем у моделей Kenney (нормали) — если будут «отстающие линии», смотреть `hull()` в scene.ts.

## Как проверять визуально

Собрать `npx ng build --output-path /tmp/...`, раздать статику с SPA-фолбэком (python http.server, 404 → index.html),
снять Playwright'ом (chromium предустановлен) с подменой `/api/**` моками и `localStorage['santa.session']='x'`.
Смотреть скриншоты самому перед отчётом. Не оставлять `web_app/dist` и `.angular` в репо.

## Качество кода (CI: `.github/workflows/ci.yml`)

- **Перед каждым коммитом:** `./scripts/check.sh --fix` — форматирует, автоисправляет и прогоняет всё то же, что CI.
  Коммитить только когда он зелёный. Без `--fix` — только проверка.
- Бэкенд (`bot/`, всё через `uv run --no-sync …`, зависимости `uv sync --group dev`):
  - форматирование и линт — **ruff** (`ruff format`, `ruff check --fix`); настройки в `bot/pyproject.toml` (строка 100);
  - типы — **ty** (`ty check`): новый код с аннотациями, без `Any` без нужды; подавлять только точечно
    `# ty: ignore[rule]` с причиной;
  - тесты — `pytest` (в CI ещё и на Postgres 17);
  - `requirements.txt` (из него ставит Docker) генерируется из `uv.lock`: после смены зависимостей
    `uv export --locked --no-dev --no-hashes --no-emit-project --no-header -o requirements.txt`.
- Фронт (`web_app/`):
  - форматирование — **`bun fmt`** (встроенный в bun ≥1.4, читает блок `prettier` в package.json и `.editorconfig`;
    prettier ставить не нужно): `bun run format` / `bun run format:check`. Скрипт нельзя называть `fmt` — `bun fmt` его вызовет;
  - линт — **ESLint** + angular-eslint (`bun run lint`, конфиг `eslint.config.js`);
  - типы — `bun run typecheck` (tsc, strict) + `ng build` (strictTemplates проверяет шаблоны);
  - `bun run check` — всё сразу.
- Скрипты — `shellcheck scripts/*.sh`.

## Формат коммитов

`<эмодзи> <тип>(<область>): <Описание>` — описание по-английски, с заглавной буквы, в повелительном наклонении,
без точки в конце, до ~72 символов. Область — необязательна, но желательна (`tree3d`, `api`, `bot`, `mailer`,
`shop`, `ci`, `deps`, `docs`…). Пример: `✨ feat(tree3d): Add new snowfall effect`.

| Эмодзи | Тип | Когда |
|---|---|---|
| ✨ | feat | новая возможность |
| 🐛 | fix | исправление бага |
| ♻️ | refactor | переделка без изменения поведения |
| ⚡️ | perf | производительность |
| 🎨 | style | форматирование, стиль кода |
| 💄 | ui | вид / вёрстка / визуал без новой механики |
| ✅ | test | тесты |
| 📝 | docs | документация, CLAUDE.md |
| 🔧 | chore | конфиги, скрипты, служебное |
| 👷 | ci | CI |
| ⬆️ | deps | обновление зависимостей |
| 🗃️ | db | схема БД / миграции |
| 🔥 | remove | удаление кода/файлов |

Тело коммита (по желанию) — что и зачем, через пустую строку после заголовка.

## Правила работы

- Коммитить и пушить в рабочую ветку; PR не создавать без просьбы.
- Перед сдачей: `./scripts/check.sh --fix` (бэкенд-тесты, типы, линт, `ng build`), скриншоты изменённого.
- Тяжёлые независимые куски можно отдавать субагенту (владелец просил экономить лимиты; механика — Sonnet),
  разводя их по разным файлам.
