# Тайный Санта — контекст проекта для Claude

Читай это перед работой. Здесь всё, о чём договорились с владельцем (общение на русском,
владелец сидит с телефона: отвечать коротко, результат первым, скриншоты прикладывать путями).

## Что это

Новогодний «Тайный Санта» со всего мира. Каждый участник пишет поздравление незнакомцу;
ровно в 00:00 по своему часовому поясу каждый получает анонимное поздравление от случайного
участника и может ответить реакцией / анонимным ответом. Прошлый сезон: Telegram-бот, 11 участников.
Цель сезона: больше участников и «вау»-атмосфера. Бюджет: только VPS + домен.

## Архитектура (рабочая ветка `claude/secret-santa-multiplatform-bnfqt3`)

- `bot/` — Python 3.13, aiogram 3 (бот) + FastAPI (API) из одного образа.
  - `src/main.py` — бот: вебхук (aiohttp, `/telegram/webhook`, порт 8080) если задан `WEBHOOK_URL`,
    иначе polling (локальная разработка). Ставит кнопку меню на Mini App (`WEBAPP_URL`).
  - `src/api_main.py`, `src/api/` — API `/api/*` (порт 8000). Авторизация: `Authorization: tma <initData>`
    (Mini App, HMAC по токену бота) или `Bearer <token>` (сайт/PWA: Telegram Login Widget, код на почту или Google →
    наш подписанный токен). Вход, привязка, слияние, уведомления — `api/accounts.py`, зависимости — `api/deps.py`.
    Медиа отдаются по подписанным URL с поддержкой Range.
  - `src/timezones.py` — пояса в формате `UTC+3`, `UTC+5:30`; есть UTC+13/+14 и получасовые.
  - `src/services/delivery.py` — `Delivery` = коробка (одна на пользователя на год), в ней письма `Letter`
    (поздравление или письмо создателей; у каждого своя реакция/ответ). Сколько писем — см. «Письма в коробке».
    Реакции/ответы (`react` по id письма), статистика. `src/services/creators.py` — письмо от создателей.
  - `src/services/mailer/` — рассылка раз в минуту, идемпотентно (не пропускает пояса, не дублирует).
  - `src/services/mandarins.py` — валюта 🍊, леджер `MandarinTx` (одна награда на user/reason/ref).
  - `src/services/tree.py` — данные ёлки: шары (box/hung/lit), звезда, гирлянда, уровень праздника 1–10.
  - `src/db/core.py` — `create_all` + идемпотентные `ALTER ... IF NOT EXISTS` (миграции без alembic),
    advisory lock (бот и API стартуют одновременно).
  - Тесты: `cd bot && uv run pytest` (SQLite); на Postgres:
    `TEST_DB_URL=postgresql+asyncpg://... ` (локально был postgres 16 в `/usr/lib/postgresql/16/bin`).
- `web_app/` — Angular 21 (standalone, signals). Один фронт = Telegram Mini App + сайт + PWA.
  - Зависимости ставить **bun** (`bun install`), не npm (у npm баг с этим lock-файлом). Сборка `npx ng build`.
  - `core/` — `telegram.ts` (обёртка WebApp; скрипт telegram.org грузит `tg-bridge.ts` до старта приложения: только в Mini App,
    таймаут 3 с, иначе свой мост по протоколу web-events — у части пользователей telegram.org заблокирован; в index.html его не ставить), `api.ts`, `store.ts` (состояние, гарды), `i18n.ts` (RU/EN; словари `i18n-ru.ts`/`i18n-en.ts` грузятся лениво, только нужный), `time.ts`.
  - `pages/` — home (ёлка, отсчёт, приглашение, «новогодняя волна»), register, new-wish (с конструктором шара),
    my-wishes, inbox (реакции/анонимный ответ), login (Telegram Login Widget).
  - `components/tree3d/` — 3D-сцена (three.js, лениво грузится, без WebGL / `?scene=2d` → 2D-ёлка `components/tree/`):
    - `scene.ts` — мир: двор, постамент, забор с фонарями, домик (`cabin.ts`), лес/горы, снег, шары, гирлянда,
      звезда, паровозик (уровень ≥6), уголки с фигурами, режим «Украсить двор», камера (360°, зум, подлёт к уголку).
    - `tree-model.ts` — ель (гладкие ярусы + пушистый снег, ~24k треугольников). `treeRadius()` обязан совпадать с геометрией.
    - `models.ts` — модели **Kenney Holiday Kit (CC0)** из `public/models/holiday/` (лицензия лежит рядом), toon-материал + контур.
    - `layout.ts` — анти-пересечения: «следы» объектов из кругов (длинные модели = ряд кругов), resolve.
    - `?debug` в URL выставляет `window.santaTree` (для скриншотов).
- Локально через туннель: `./scripts/dev-tunnel.sh` (настройки `.env.dev`, см. `.env.dev.example`): cloudflared/ngrok/ssh →
  `ng serve :4200` (прокси `/api`→8000, `/telegram/webhook`→8080), бот на вебхуке, SQLite в `.dev/`; по Ctrl+C снимает вебхук и кнопку.
- Деплой: `docker-compose.yaml` (db, state_storage, bot, api, web=Caddy с авто-HTTPS), `.env.example`,
  инструкция `docs/DEPLOY.md`. PWA: `public/manifest.webmanifest`, `public/sw.js`, иконки.
  Кеш: `sw.js` отдаёт из кеша без проверки только файлы с хешем в имени (`main-AB12CD34.js`), всё остальное — сначала
  сеть (кеш только для офлайна); навигация — сначала сеть. В dev-режиме (`ng serve`, в т.ч. через туннель) service worker
  не ставится, а оставшийся снимается вместе с кешем (`main.ts`, `isDevMode()`): у `ng serve` имена без хеша, и раньше
  телефон показывал старую версию бесконечно. Меняешь логику кеша — поднимай версию `CACHE` в sw.js.

## Принятые решения

- Мобильные приложения = **PWA** (без App Store/Google Play). Позже можно TWA в Google Play ($25).
- Caddy вместо nginx+certbot. Вебхук вместо polling на проде.
- Анимации/вид в стиле «уюта» как в новогоднем событии World of Tanks (механики, а не их арт).
- 3D: three.js, мультяшный cel/toon shading с контуром (outline). Облако точек / Gaussian splatting — нет.
- Модели: Kenney (CC0). Unity Asset Store — нет (лицензия). Всё, что берём, — только CC0/проверенная лицензия.
- Пакет для окружения: создано облачное окружение `secret_santa` с доступом к kenney.nl.

## Игровая механика (сделано)

- **Письма в коробке (решено с владельцем):** каждое одобренное поздравление сезона должно до кого-то дойти, и все
  шары загореться. При открытии коробки (`DeliveryService._fill`) кладётся доля: недоставленные поздравления сезона
  (свои тоже считаются) / ещё не открывшие (живые аккаунты), с округлением вверх, минимум 1, максимум `MAX_LETTERS` = 5.
  Поздравления, написанные позже, уходят тем, кто открывает позже. Поздравлений меньше, чем людей — одно поздравление
  получают несколько (наименее доставленные первыми, среди равных случайно); реакции/ответы автор видит от всех.
  Никогда не своё и не одно дважды в коробке. Все письма — сразу, в полночь (отдельные письма на Рождество —
  возможная будущая фича). «Дошло +20» — один раз на поздравление (ref = id поздравления), реакция/ответ — на письмо.
  Старые коробки с одним `wish_id` превращаются в одно письмо с тем же id (`LETTERS_MIGRATION` в db/core.py).
- **Письмо от создателей:** сверху в каждой коробке (`Letter.creators`), текст RU/EN + подпись в БД
  (`CreatorsLetter`, строка на сезон; API при старте кладёт черновик из `services/creators.py`, если строки нет —
  правленый текст не перетирается; править пока вручную в БД, позже через админку бота). Реакции и ответ можно, но
  без мандаринок и уведомлений; ответы лежат в `letter.reply` (просмотра для админа пока нет).
- Синтетические поздравления на случай «никто не написал» — позже заранее наполнить БД (пометить флагом,
  не считать в статистике и наградах). Пока не сделано.

- Каждое поздравление = шар на ёлке пользователя: 🎁 коробка под ёлкой (на модерации) → висит (одобрено)
  → **горит** (дошло до получателя в НГ). Цвет (8) и узор (6) выбираются при написании.
- Звезда и гирлянда на ёлке разгораются с уровнем праздника (доля = уровень/10), в полную силу — на 10-м уровне
  (решено с владельцем: раньше звезда ждала открытия подарка — ёлка была тусклой). Друзья по-прежнему зажигают
  огоньки гирлянды (берётся большее). Поле `star` в API осталось только для очков уровня.
- Полоска уровня — путь от 1 до 10 целиком (каждый уровень заполняет 1/9), а не прогресс внутри уровня.
- Уровень праздника 1–10 меняет сцену: ≥3 фонари/окна, ≥5 гирлянда на заборе, ≥6 паровозик, ≥9 северное сияние.
- Мандаринки 🍊 (только за действия, не продаются): одобрено +30, дошло +20 (раз на поздравление), реакция +5, ответ +10,
  друг пришёл +15 и друг написал одобренное +50 (оба — при первом одобренном поздравлении друга), открыл подарок +50.
- Рефералы: `t.me/<bot>?start=r_<uuid hex>`, на сайте `?ref=` (без бота ссылка приглашения — на сайт).
- Двор: 5 уголков у забора («у крыльца», «у фонаря», «снежная горка», «у камней», «у тропинки»), в каждом
  горка подарков, вокруг места под фигуры. Правила стойки по типу: персонажи смотрят на ёлку, сани боком,
  трости/фонари как угодно; выбирается поза с минимальным сдвигом; без пересечений.
- Режим «Украсить двор»: издалека большая голубая стрелка над горой → подлёт камеры к уголку (большая стрелка
  этого уголка гаснет по `focusBlend`, `focusedCorner`) → маленькие стрелки над местами (`SMALL_ARROW` = 1.4, хит-цилиндр r 0.85 — под палец); Подсказка зависит от вида.
  **Примерка (решено с владельцем):** нажал стрелку → список свободных фигур → выбранная появляется полупрозрачным (70%)
  превью **только на этом месте**, на остальных остаются стрелки → «✓ Поставить сюда» (или тап по превью) ставит по-настоящему,
  режим не закрывается. Другая стрелка — выбор заново. Из лавки («Поставить во двор») фигура уже выбрана: тап по стрелке
  сразу примеряет её, без списка. Нажатие на стоящую фигуру — как раньше: заменить / убрать. В сцене это
  `setDecorMode(on, {item, pad} | null)`; двор перестраивается без дублей (`courtyardParts`).
  Назад от уголка ко всему двору, не выходя из режима: кнопка «← Весь двор» над «Готово», отдаление (колесо, щипок, «−»
  — `zoomOutOfFocus`) или поворот сцены пальцем.
- Пустое место под новый шар медленно «дышит» и светится.
- Рельеф (`components/tree3d/terrain.ts`): неровная снежная поверхность с сугробами и контуром (outline по гребням);
  ровно на площади, у домика и на тропинке. Объекты на снегу берут высоту из `terrainHeight()`.
- Гирлянда под крышей домика (`cabin-lights.ts`): скин = форма + цвета + программы анимации (`SKINS`). Формы: бахрома
  (разноцветная/тёплая/золотая/ледяная/леденец), бахрома со снежинками (`flakes`), радуга — 6 вложенных провисающих линий,
  каждая своя гирлянда (`rainbow`), трубки-«метеоры» (`meteor`); звёздочки 5-лучевые (`stars`) и 4-лучевые (`sparks`) — бахрома, где лампочка = объёмная
  звезда (`bulb` в `SKINS`, `starGeometry`), смотрит от стены и покачивается на проводе;
  звёздная радуга (`starbow`: радуга из 5-лучевых) и звездопад (`starfall`: метеоры из 4-лучевых). Программы сменяются как у контроллера настоящей гирлянды
  (бег, мерцание, волна, капли, заполнение, каскад линий, перелив цветов…), длительность — `TUNING.lightsProgramS`; нажатие на домик → камера к домику + компактная полоска выбора, закрытые скины можно примерить.
  `skins.ts` без three.js — UI импортирует только его (иначе three.js попадает в основной бандл).
- Смена погоды плавная (`TUNING.weatherMs`): число снежинок, размер, ветер, звёзды, сияние, блеск снега переходят
  постепенно; лишние снежинки гаснут/проявляются по одной (атрибут `order`, униформа `shown` в шейдере снега).
- Кликабельные объекты сцены (шары, звезда, подарки, домик, фигуры, стрелки) реагируют: под мышью чуть растут и курсор
  «рука», под пальцем приседают и пружинят обратно. Хит-меш несёт `userData.react` (что масштабировать) и `amount`;
  масштаб накладывается только на время отрисовки кадра (`applyReactions`/`restoreReactions`), свои анимации объектов не ломаются.
- Загрузка сцены без зависания: `TreeWorld.build()` строит мир по шагам с кадром между ними, `finish()` ждёт модели и
  компилирует шейдеры `compileAsync`; до этого ничего не рисуется (`live`). Пока грузится — экран с «кипящими»
  карандашными рисунками (вид `doodle` в handmade.ts: `data-doodle` = snowflake/star/fir) и полоской прогресса.
- Погода: ясно (звёздное небо, бесплатно) / лёгкий снег (бесплатно) / снегопад (150 🍊) / метель (400 🍊) — кнопка ❄️ на сцене; плотные режимы
  покупаются в лавке (см. «Лавка»).
- **Время суток** (`tree3d/daytime.ts` — палитры и астрономия без three.js, `core/daytime.ts` — выбор и место): вид двора
  зависит от **настоящего солнца** — высоты над горизонтом и половины дня (`SunPlace`: elevation, hourAngle в градусах).
  Ключи по высоте: ниже −12° ночь, −6° синий час, 0° рассвет (утром) / закат (вечером), 6° утро / после полудня, от 15° день;
  утро и вечер смешиваются около полудня и полуночи. Решено с владельцем: **по-честному** — ранняя темнота северной зимы,
  полярная ночь (в полдень сумерки), долгие светлые вечера южного лета. Место — главный город часового пояса устройства
  (`Intl…timeZone` → `core/zones.ts`, таблица из tz database, ленивый чанк ~4 КБ), без геолокации, ничего не уходит на сервер;
  неизвестный пояс — долгота по смещению устройства, широта 50°. Это место по умолчанию; в окне времени суток (режим
  «Как у меня») — «📍 Город · Уточнить место»: поиск по встроенному списку `core/cities.ts` (~270 городов `ru|en|lat|lon`,
  много северных, ленивый чанк; поиск никуда не ходит) или геолокация браузера (округление до 0.1°, имя — ближайший город
  списка в пределах 120 км), «Вернуть по часовому поясу». Хранится только в `localStorage['santa.place']` (решено с
  владельцем: всё остаётся в браузере).
  **Город и часовой пояс аккаунта согласованы (решено с владельцем):** у городов `cities.ts` есть смещение на новогоднюю
  ночь (5-е поле, минуты, из tz database — летнее время южного полушария учтено). Город (или геолокация) в другом
  поясе — сначала вопрос «Встречаешь Новый год там? Да, перейти на UTC+7 / Нет, оставить UTC+3» (`pendingPlace` в
  tree-panel, `Daytime.timezoneFor`); «да» меняет пояс аккаунта (`saveProfile`, на сервер уходит только пояс) + тост,
  «нет» — город не меняется (решено с владельцем: город и пояс не расходятся); пояс, сменённый на странице регистрации, отодвигает
  выбранный город другого пояса — берётся город по умолчанию нового пояса (город устройства, если пояс совпадает с
  устройством, иначе первый город списка с этим смещением). Это вычисляется (`Daytime.place`), а не хранится. Часы,
  восход и закат пишутся по времени места, не устройства. На регистрации под поясом — «например, в городах: …». Маскот ненавязчиво говорит об этом одной репликой темы `tip` у каждого характера. Формула солнца — `sunPlace()`, восход/закат — `sunTimes()` (в окне выбора
  пишем их или «полярная ночь/день»). Что меняется: небо (униформы шейдера), туман (днём реже, `fog.far`), полусфера,
  главный свет (солнце, ночью луна), диски солнца и луны, звёзды/сияние/падающие звёзды (только тёмное ясное небо), bloom
  (днём выше порог — снег не светится), горы (ночные цвета вершин → дневные). Фонари и окна горят при уровне ≥3 **и**
  `dark ≥ 0.5`. Облачность снегопада делает небо серее и гасит солнце. Кнопка над ❄️: «Как у меня» (пересчёт раз в минуту
  без перехода) / утро / день / вечер / ночь (`DAYTIME_FIXED`), бесплатно (решено), `localStorage['santa.daytime']`;
  ручная смена — плавно за `TUNING.daytimeMs`. 2D-ёлка время суток не показывает.
- Северное сияние (уровень ≥9): отдельные колышущиеся ленты над лесом; видно только в ясную/слабоснежную погоду.
- Шары висят на нитях с кончиков веток нижнего края ярусов (кроме самого нижнего), нить отклоняется от веток.
- Снег (`tree3d/snow.ts`): свой мягкий toon-градиент + холодный «пушистый» ободок (`snowMaterial`), искры-блёстки
  (`buildGlitter`: земля, постамент, ёлка, крыша; мерцают от времени и поворота камеры). Весь снег красить через `snowMat()`.
  Снег на крыше домика — одна гладкая поверхность через конёк (`roofSnowGeometry` в cabin.ts): высота = функция (x, z),
  кромка заворачивается и уходит внутрь кровли (без зазора и самопересечений). Коробкой больше не делать.
- Живость (`tree3d/life.ts`): снегири на столбах забора (прыгают, клюют, перелетают), падающие звёзды в ясную погоду,
  следы от крыльца к калитке; фигуры во дворе шевелятся (`idle()` в scene.ts), огонь фонарей/окон мерцает, дым паровозика шлейфом.
- Фонарь — один ассет (`tree3d/lantern.ts`, `lanternFactory`): столбы забора и крыльцо ставят его через `build(scale)`,
  включение/выключение всех разом — `setOn()`. Новые фонари добавлять только так, не собирать из боксов на месте.
- Свет фонарей — настоящий (`PointLight` в каждом фонаре, `LANTERN_LIGHT` в lantern.ts): падает на снег и предметы вокруг,
  мерцает вместе с огнём; спрайт остаётся только маленьким ореолом пламени. На слабых устройствах (`realLightsWanted()` в
  scene.ts: <6 ядер или <4 ГБ) — прежний большой спрайт-ореол без источников света; принудительно `?light=real|simple`.
  Свет фонаря падает только на грани, повёрнутые к нему (колпак сверху и снежная шапка остаются тёмными): toon-затенение
  даёт отвёрнутым граням самую тёмную полосу, поэтому `facingLights()` правит чанк three.js для источников с
  `decay == FACING_DECAY`; свет внутри ёлки (`treeLight`) оставлен как был. Теней (заслонения предметами) нет.
  Окна домика (кроме заднего) в «настоящем» режиме светят `SpotLight`-конусом наружу и вниз на снег (`WINDOW_LIGHT`,
  `windowSpots` в cabin.ts), спрайт-«лужа» света тогда скрыт. Гирлянда домика светит одним общим `PointLight` (был и раньше).
  Гирлянда на заборе, шары, звезда — только светящийся материал, вокруг не светят.
- Свечение в «настоящем» режиме — **bloom** (штатная постобработка three.js: `EffectComposer` + `UnrealBloomPass` в scene.ts),
  самодельного свечения нет. Светится всё, что ярче белого (порог 1.0): источники красятся через `emit(color, power)` из
  glow.ts (`BLOOM_POWER`) — стекло фонарей, звезда, горящие шары, гирлянды ёлки/забора/домика, окна; стекло фигуры-фонаря
  выделяется по цвету текселя (`lampGlass`). Ореолы источников делать через `this.halo()` — в «настоящем» режиме он скрыт,
  в простом это прежний спрайт; `this.glow()` — для того, что должно остаться спрайтом всегда (луна, стрелки, подсказки).
  Кадр при bloom рисуется в линейный буфер: свои шейдеры, пишущие «экранные» цвета, обязаны заканчиваться
  `gl_FragColor = sRGBTransferEOTF(gl_FragColor); #include <colorspace_fragment>` — иначе всё светлеет.
  Интерфейс фонаря: `Lantern.shine(k)`.
- Ореолы-спрайты (`glow.ts`, `pushForward`): глубина проверяется ближе к камере, чем сам спрайт, — модели, вокруг которых
  он светится, его не «режут», а всё, что реально спереди, по-прежнему заслоняет. Новые ореолы делать через `this.glow()`.
  Фигура-фонарь из лавки горит всегда (`lightFigureLantern`), её источник (`figureLight`) создан заранее — добавление
  источников на лету пересобирает шейдеры.
- Снежные шапки (столбы, труба, фонарь) — замкнутые формы: кромка заворачивается и уходит в опору, без «среза» снизу.
- Северное сияние рисуется шейдером (лучи разной ширины и высоты, зелёный низ → розовый → фиолетовый), не текстурой.
- Места под шары: все ярусы кроме нижнего, шаг ~0.62; порядок заполнения — «самое дальнее от занятых», чтобы любое
  число шаров ложилось равномерно по всей ёлке.
- Блеск снега — в самом материале (`snowMaterial`, шейдер): кристаллики по мировой сетке, каждый вспыхивает, только когда
  «смотрит» на камеру, поэтому блики меняются при вращении; сила/плотность — константы `SPARKLE_*`. Крупные звёздочки
  (`buildGlitter`) оставлены как редкий акцент.
- Снежинки: атлас 2×2 (мягкая + три шестилучевых кристалла), вращаются в шейдере; каждая третья — крупный кристалл.
- Дым (труба, паровозик) — объёмные cel-клубы с контуром (`buildPuff`/`puffScale` в life.ts), не размытые спрайты.
- Горы: один low-poly меш со снежными шапками, без тумана (цвета уже ночные).
- Контур (outline.ts): экранной толщины, у забора, домика, моделей Kenney и леса (instanced). Ночь затемнена для контраста со светящимся.

## Аккаунты без Telegram (сделано)

- Решено с владельцем: приложение (сайт/PWA) работает **без Telegram**. Вход: код на почту, Google, Telegram Login
  Widget; в Mini App — как раньше (initData). Аккаунт `User` хранит до трёх способов входа: `telegram_id` (теперь
  необязателен), `email`, `google_id` (все уникальны); `name` — имя для тех, кто вошёл не через Telegram.
- Токен сессии называет **способ входа** (`{"k": kind, "v": key}`), а не аккаунт: после слияния он ведёт в общий аккаунт.
  Старые токены `{"id": tg_id}` работают. `Principal` в `api/auth.py`; пользователь ищется `accounts.get_user()`.
  Сервисы подарков принимают `who: int | UUID` (Telegram id из бота или id аккаунта из API).
- Почта (`services/email.py`, stdlib smtplib, `SMTP_*`): код 6 цифр, `EmailCode` (хеш, 10 мин, 5 попыток, не чаще раза
  в минуту) + лимит 8 писем с IP за 15 мин. Без `SMTP_HOST`, но с `DEBUG_TOOLS=1` письма пишутся в лог (код виден там).
- Google (`services/google.py`, PyJWT + ключи Google, `GOOGLE_CLIENT_ID`): если у Google-входа нет аккаунта, но
  подтверждённая почта совпадает с чьей-то — Google привязывается к нему сам. В Mini App Google не показываем (webview).
- Привязка — «Настройки» (`/settings`, значок ⚙ в выходных данных листа; рядом значок темы — квадратные `.icon-btn`): `POST /api/me/link` с доказательством входа.
  Если у этого входа свой аккаунт — `taken` + `merge_token` (подписан, 15 мин) и сводки обоих; `POST /api/me/merge`.
  **Слияние** (`accounts.merge`, остаётся аккаунт, из которого привязывали): поздравления, push-подписки, друзья
  переезжают; мандаринки складываются, но одинаковая награда (reason+ref) не удваивается, а покупки остаются (новый ref);
  награды «друг пришёл/написал» друг за друга удаляются; фигуры сверх `MAX_COPIES` (и вторые копии огней/погоды)
  возвращаются мандаринками по цене (`merge_refund`), фигура на занятом месте убирается со двора; подарок года — один:
  остаётся открытый (если оба — наш). Способы входа, которых у оставшегося нет, переходят к нему; часовой пояс —
  по выбору. Отвязать можно любой способ, кроме текущего и последнего.
  **Никакой случайности (решено с владельцем):** где у обоих своё и остаётся одно, человек выбирает (`MergeChoices`:
  timezone, language, notify, telegram/email/google — если у обоих свой, yard — чьи фигуры на общих местах, gifts —
  чей подарок за год, где оба открыли). Сервер сам находит такие места (`MergeReport.conflicts`), окно показывает их
  с выбранным «этот аккаунт» и пересчитывает превью на каждый выбор (`POST /api/me/merge/preview`). Если ушёл способ,
  которым вошла эта сессия, `merge` отдаёт новый `token` (вход тем же видом из того аккаунта). В Mini App Telegram
  менять нельзя (`locked`, `Principal.via_tma`).
- Уведомления (`services/notifier.py`): `User.notify` — каналы через запятую (`telegram,push,email`, None = все).
  Подарок в полночь — во все выбранные (рассылка `mailer` шлёт Telegram сама, остальное через `notifier.gift`);
  реакции/ответы и модерация — Telegram + push, без писем. Тексты RU/EN по `User.language` (сайт передаёт язык при
  регистрации).
- Push (`services/push.py`, pywebpush, VAPID `VAPID_*`; ключи — `python -m services.push`): `PushSubscription`,
  мёртвые подписки (404/410) удаляются. Клиент — `core/push.ts` (iPhone — только с экрана «Домой», в Mini App нет),
  показ — `push`/`notificationclick` в `public/sw.js` (версия кеша v3). В dev-режиме service worker нет — push не проверить.
- Фронт: `components/sign-in.ts` — общий блок входа (Google / Telegram / почта), режим `login` или `link`;
  `pages/login.ts`, `pages/settings.ts`. Поле ввода — класс `.input` (рисованная рамка `field`), варианты — `.choice`.
- **Превью объединения:** `accounts.preview_merge` делает настоящее слияние в транзакции и откатывает её — итог
  (`MergePreview.result`) и отчёт (`MergeReport`: возврат копий, убранные со двора фигуры, неудвоенные награды, потерянные
  подарки, отвязанные способы входа) точно такие, как будут. В окне — таблица «Этот / Тот / Итог» и правила списком
  (только те, что касаются этих двух аккаунтов). Тест сверяет превью с результатом настоящего слияния.
- iPhone: push только у сайта с экрана «Домой». `Install.iosBrowser` (Safari на iPhone/iPad не с экрана «Домой») →
  в настройках блок с шагами (`components/ios-steps.ts`, общий с карточкой установки), карточка установки на iPhone
  с первого визита и объясняет про уведомления.
- **Безопасность входа и объединения (проверено по просьбе владельца, тесты в test_accounts.py):**
  - Модель: доказал любой способ входа аккаунта = можешь войти в него (и увидеть всё). Знать чужой Telegram/почту
    мало: Telegram — подпись виджета, почта — код из письма, Google — подписанный токен для нашего client id.
  - Доказательства одноразовые (`UsedProof`, sha256): данные виджета (живут 10 мин, `LOGIN_MAX_AGE`) и токен Google
    нельзя повторить, даже если утекли.
  - Код почты: 5 попыток на код, **15 неверных и 10 писем в сутки на адрес** (`DAY_FAILS`/`DAY_SENDS` в `EmailCode`),
    иначе перебор 6 цифр давал ~0,7 % в сутки; плюс 8 писем с IP за 15 мин. Gmail нормализуется (точки, `+тег`).
  - Google привязывается к аккаунту по почте сам **только** для адресов Google (gmail или `hd`): аккаунт Google можно
    завести на чужой адрес (`GoogleUser.trusted_email`).
  - Менять способы входа (привязать, отвязать, объединить, превью) — только при **свежем входе** (`FreshUser`: сессия
    ≤15 мин с момента входа, Mini App ≤1 ч с открытия); иначе 403 `reauth_required` → «Подтверди, что это ты»
    (`POST /api/me/reauth` любым способом этого же аккаунта) / `reopen_required` в Mini App. В токене `iat` = момент входа.
  - Чужая почта в превью и окне объединения маскируется (`mask_email`: a***@g***.com).
  - Уведомления безопасности (`notifier.security`): привязка, отвязка, объединение — во все каналы аккаунта (Telegram,
    почта, push), независимо от настроек; ушедший способ входа (отвязанный, проигравший при слиянии) тоже получает письмо.
  - Объединение: подарок, не оставшийся при слиянии, уносит и свою награду за открытие (без двойных +50).
  - **Друг засчитывается только после первого одобренного поздравления** (решено с владельцем: почтовые аккаунты
    дёшевы): `shop.active_friend` — для фигур за друзей, гирлянды, «Приглашено»; «друг пришёл» +15 и «друг написал» +50
    начисляются вместе при одобрении (`WishService._reward_approved`). `/api/me`: `invited` (засчитаны) и
    `invited_pending` (пришли, ещё не засчитаны).
  - **Сеансы** (`services/sessions.py`, таблица `Session`): каждый вход на сайте/PWA — строка (устройство из
    User-Agent «Chrome · Android», только сетевая часть IP «95.31.*.*», создан, последняя активность — пишется не чаще
    раза в 5 мин); токен несёт `sid`, удалённая строка = токен больше не работает (`deps.current_principal`). Сеанс
    привязан к способу входа (kind+key), а не к аккаунту: при слиянии следует за ним. «Где выполнен вход» в настройках
    (`GET /api/me/sessions`), «Завершить» конкретный (`DELETE /api/me/sessions/{id}`), «Выйти» завершает свой на сервере
    (`POST /api/me/logout`). Отвязка/проигрыш при слиянии/стирание завершают сеансы этого способа входа.
    Mini App входит через Telegram — сеанса нет, в списке не показывается.
  - **Выйти на всех устройствах** (`POST /api/me/logout-all`): удаляет все сеансы, кроме текущего; для старых токенов
    без `sid` — ещё `User.sessions_after` (токены с меткой создания `t`, мс, раньше неё не принимаются).
  - **Удаление с восстановлением 30 дней** (решено с владельцем): `DELETE /api/me` (свежий вход) ставит `deleted_at`,
    выходит на других устройствах; аккаунт скрыт везде (рассылка, выбор поздравлений, друзья, статистика, объединение —
    `link` отвечает `deleted`), API отвечает 403 `account_deleted`, `/api/me` — `{deleted, purge_at}` → страница
    `/deleted` («Восстановить» — `POST /api/me/restore`, «Стереть сейчас» — `POST /api/me/erase`, свежий вход). Бот вместо
    меню пишет, что аккаунт удалён. Через 30 дней фоновая задача бота (`accounts.purge_deleted`, раз в 6 ч) стирает всё;
    у получателей поздравление помечается стёртым (`Delivery.wish_erased`, во «Входящих» — своё объяснение).
  - Не сделано: одноразовые почтовые домены (см. «План», п. 9).
- Тесты — `bot/tests/test_accounts.py`. Миграция старой БД: Postgres — `ALTER` в `db/core.py`, SQLite пересобирает
  таблицу `user` (`_sqlite_user_identities`). Проверено на обеих.
- Не сделано: напоминания/реакции письмом, смена почты одной кнопкой (сейчас: отвязать → привязать), бот не знает о
  веб-аккаунте человека (нажал /start в боте до привязки → новый аккаунт, потом объединяется в настройках).

## Интерфейс: «бумажный табель» (сделано, первая версия)

- Образец стиля — печатный табель-календарь (референс владельца: календарь «Мира танков»; берём приёмы, не их арт):
  лист фактурной бумаги на фоне «стена + крашеная полоса», тонкие линейки, цифры и заголовки с засечками
  (Roboto Slab, пакет `@fontsource-variable/roboto-slab`, шрифт раздаём сами), красные рамки-штампы, 3D-сцена — «иллюстрация» листа.
- Две темы: светлая бумага и тёмная («тот же лист ночью»). Токены в начале `styles.scss` (`--paper*`, `--ink*`, `--rule*`,
  `--stamp`, `--orange`, `--rarity-*`), тёмные — `:root[data-theme='dark']`. `core/theme.ts`: авто (Telegram `colorScheme` /
  система) → светлая → тёмная, выбор в `localStorage['santa.theme']`, кнопка в «выходных данных» внизу листа.
  Цвета в компонентах — только токенами, без «зашитых» hex (иначе ломается одна из тем).
- «Человечность» — рамки, линейки, штампы и кляксы не CSS-прямоугольники, а штрихи «от руки»: `core/handmade.ts` находит
  элементы по селекторам из `RULES` и кладёт в каждый SVG-слой `svg.hm` (текст не трогается). Приёмы (подсмотрены в
  открытых наборах для рисованной анимации кодом): точки пути дрожат и сглаживаются кривой; **карандаш** — три прохода
  (основной и два лёгких рядом), нажим меняется по длине (линия то тёмная, то еле видна, местами рвётся), концы сужаются;
  рамка = четыре отдельных штриха с перелётом за углы; заливка — три неровных слоя со сдвигом и тёмной кромкой; зерно
  грифеля — см. ниже. Случайность задаётся
  зерном элемента: перерисовка при изменении размера даёт тот же рисунок. «Кипение» (4 варианта по кругу, 6 кадров/с) — только
  у печати и главной кнопки (`BOILING`), выключается при «меньше движения». Цвет рисунка — CSS-переменная `--hm`.
  Новый рисованный элемент = строка в `RULES` + цвет в styles.scss; CSS-рамку/фон у него убрать. Рамка сцены `hm-picture` — без зерна. Листки отсчёта и цифры слегка повёрнуты по-разному.
- Заливки (решено с владельцем): **большие площади** (рамка-штамп с отсчётом и подобные) — акварель (`paint()`);
  **остальное** (кнопки, пятна под значками) — карандашная штриховка широкой линией (`hatch()`): штрихи одного
  направления, угол каждого гуляет на пару градусов («в пределах человечности»), разный нажим, неровные концы, редкие
  пропуски; у кнопок бледная основа + два прохода + тёмный контур. Перекрёстная штриховка — только под фигурами в лавке.
  Кнопки с ценой — еловый зелёный `--buy` (🍊 не сливается).
- Фактура карандаша — не SVG-фильтр, а тайловые CSS-маски, которые handmade.ts делает один раз при запуске из одного
  поля шума: «зуб бумаги» (`toothField()`: четыре слоя гладкого шума разного масштаба, как у Перлина, + немного мелкого
  зерна; пятна не крупнее ~4,5 px, иначе на светлых заливках читаются как грязь; плитка бесшовная, в разрешении экрана,
  до 3 точек на CSS-пиксель). `toothMask(name, field, min)` кладёт плитку в переменную через blob-URL: `--hm-grain`
  грубая для линий, `--hm-grain-soft` лёгкая для штриховки (текст на кнопке должен читаться), `--m-grain` /
  `--m-grain-dark` для маскота. Прежнее точечное зерно («песок») убрано. Фильтры на каждый слой тормозили панели.
  Край линий мягкий (тон плавно слабеет к границе), концы круглые; «рваный» край с зубцами владелец отверг — не делать.
  У линий-лент (`pencilPass`): точки идут часто (`DENSE`), каждая сторона ленты плавно гуляет сама (гладкий шум `EDGE*`),
  вокруг куска тонкая полупрозрачная кромка (`.hm-pencil`); кусок скругляется дугой там, где карандаш опустился или
  оторвался (начало/конец линии, разрыв), между соседними кусками стык плоский (иначе тёмное пятно). У штриховки
  (`hatch`): кусок = группа с общей прозрачностью из трёх копий линии — тело и два более широких и бледных ореола
  (суммарная толщина как у прежнего штриха, иначе пропадают промежутки); каждая копия идёт своей слегка волнистой
  дорожкой (`wavy`, `sway`), поэтому мягкая кромка ещё и неровная — то шире, то уже; на концах штриха копии сходятся.
  Два свободных конца всей линии — полукруги (`hm-cap`). Край должен быть и мягким, и заметно неровным (плавно).
  Слой `svg.hm` больше элемента на `PAD` = 14 px со всех сторон (в CSS `left/top: -14px`) — иначе маска обрезает перелёты.
- Отклик кнопок (`BUTTONS` в handmade.ts): наведение мышью — «кипящая» кнопка замирает, обычная один раз перерисовывается,
  обе становятся ярче (`.hm-hover`); нажатие — рисунок «растекается» (крупнее и жирнее, `press` в `draw()`) и чуть темнеет
  (`.hm-press`). На тач-устройствах наведения нет, работает только нажатие.
  Плюс **обводка**: при наведении/нажатии кнопка небрежно обводится толстым мягким карандашом одной линией «без отрыва
  от бумаги» (`scribble()`: полтора с лишним витка, каждый виток смещён и шире предыдущего). Форма повторяет кнопку:
  скруглённый прямоугольник, у круглых кнопок — кольцо. Линия режется на полупрозрачные куски с плоскими концами
  (общая точка на стыке): где карандаш прошёл дважды — тон темнее. Анимация прорисовки кусок за куском (`TUNING.scribbleMs`, core/tuning.ts);
  пока кнопка нажата — обводка остаётся. Отдельный слой `svg.hm-outline`; над сценой — белая. Толщина до 8 px,
  у маленьких кнопок тоньше (иначе кольцо сливается в пятно).
  После отпускания кнопки обводка уходит так же, как пришла, — начало линии исчезает первым (`hm-leaving`,
  `hm-unscribble`), и не возвращается, пока курсор не уйдёт и не придёт снова (`spent`).
  **Решено с владельцем:** в лавке (`QUIET` = `shop-sheet`) обводки нет — там обводка + перерисовка шумно, остаётся
  только перерисовка. Везде остальное — как описано выше.
- Штриховка — одна непрерывная линия-зигзаг «туда-обратно» (у перекрёстной — по одной линии на направление), порезанная
  на куски по `HATCH_PIECE` штрихов со своим нажимом. Развороты у края — плавные петли (кривая за край и обратно),
  без острых углов: острые стыки давали «заломы». Кусок заканчивается в начале следующего штриха, поэтому швов нет. При перерисовке от взаимодействия (наведение — 420 мс, нажатие и
  отпускание — 200 мс) штриховка прорисовывается кусок за куском (`.hm-seq`, `--i`, `--each`), а старый рисунок под ней
  гаснет (`.hm-old`); при обычной перерисовке (размер, первый показ) анимации нет. Варианты «кипения» лежат в `g.hm-v`.
- Кнопки поверх сцены (🍊, лавка, «Украсить двор», погода, зум) — бумажные ярлычки, наклеенные на иллюстрацию
  (`tag` / `tag-round`), чуть под разными углами.
- Стиль распространён на всё (таблица `RULES` в handmade.ts — единственное место, где элементу назначается рисунок):
  заголовки между линейками (`title`), рамка-штамп (`stamp`), заштрихованные блоки — главная кнопка, цены, активная
  вкладка лавки, тост (`ink-block`); рамочные вещи — кнопки, варианты выбора (погода, гирлянды, реакции, узоры шара),
  карточки и наборы лавки, переключатель темы (`card`; выбранный вариант обведён красным карандашом, класс `selected`);
  тихие кнопки одной лёгкой линией (`light`); подчёркивания цифр и активной вкладки (`underline`), линейки строк и
  подзаголовков панелей (`rule`); полосы прогресса — карандашная линия и заштрихованная часть (`bar-track`/`bar-fill`);
  цитаты, подсказки, конструктор шара, «моя» строка волны — акварельное пятно (`note`); бейджи и чипы — лёгкая
  штриховка (`chip`); поля ввода — рамка поверх поля соседним элементом (`field`, внутрь `<select>/<textarea>` не вставить).
  Виды из `BARE` получают класс `hm-bare`: CSS-фон и рамка выключаются. Перерисовка следит за классами из `STATES`.
- Просмотрены глазами в обеих темах: главная, кошелёк, погода, гирлянды, звезда, лавка (фигуры, наборы, погода),
  «написать», «мои», «подарки», регистрация. Не смотрел: вход (виджет Telegram), панель шара, панель места во дворе,
  2D-режим, английский язык.

## Маскот, правила, установка, иней (сделано)

- **Маскот** (`core/mascot.ts`, `core/mascot-lines.ts`, `components/mascot/`): Дед Мороз или Санта (рисунок SVG
  `mascot-art`) и характер: классический / весельчак (сленг и
  приколы для подростков) / сказочник / ворчун. Внешность по характеру: очки, пенсне, нахмуренные брови. Выбор — в
  `localStorage['santa.mascot']` (только этот браузер; по умолчанию RU → Дед Мороз, EN → Санта). `<mascot-says topic>`:
  облачко с репликой, тап по облачку — следующая реплика темы `more` (по умолчанию советы), тап по фигуре — окно выбора.
  Реплики: язык → характер → тема (`greet`, `tip`, `rules`, `teaser`, `install`, `write`, `gift`, `midnight`),
  токены `{me}`, `{laugh}`, `{name}`; в русских репликах нет глаголов с родом про читающего. Стоит на главной (новичку —
  `teaser` + кнопка «Как играть», в полночь — `gift`), на «Как играть», «Написать», в карточке установки.
  Живость (`mascot-art.ts` + анимации `mascot-*` в styles.scss): всегда дышит, качает головой, оглядывается, моргает,
  кончик шапки Санты качается, снежинка на шапке Мороза мерцает; пока «печатает» реплику — кивает, брови вверх, смотрит
  на облачко, рот двигается. Раз в 8–20 с — действие своего характера (`ACTS`: машет варежкой, подпрыгивает, кивает,
  оглядывается, блик очков, вздох с закрытыми глазами, мотает головой); при появлении машет (`hello`), при смене героя/
  характера подпрыгивает. Части — вложенные группы (`m-all` › `m-breath`/`m-head-act` › `m-head`), чтобы постоянные
  движения и разовые действия не перебивали друг друга. Низ халата не обрезан: халат идёт ниже, на нём штриховка,
  и всё уходит в прозрачность CSS-маской. Туловище узкое, руки висят по бокам (видны плечи) и тоже растворяются;
  обе руки одинаковые (плечо + предплечье, левая — зеркало правой); меховая отделка — одна фигура без шва:
  два треугольных лацкана «галочкой» от плеч сужаются в белую полосу по центру халата, лежит поверх рук;
  правая — с локтем: для взмаха плечо уходит в сторону (`mascot-wave`), предплечье `m-fore` сгибается вверх и качается
  (`mascot-wave-fore`), большой палец вверх и к голове; без швов (плечи, локти): сначала халат и все части рук
  с контуром, поверх — их заливки без контура (`m-fill-only`; копии движущихся частей с тем же классом двигаются вместе);
  манжета с варежкой (`m-hand`) видны только у поднятой руки.
  При «меньше движения» всё стоит.
  Техника — как у интерфейса, цветной карандаш (в тёмной теме — мел), без SVG/CSS-фильтров: заливки — SVG-узоры внутри
  рисунка (`<pattern>` на цвет: бледная основа = цвет + бумага, поверх неровные штрихи `STROKES`; id узоров свои у каждого
  экземпляра, в CSS приходят переменными `--m-fill-*`), сверху та же фактура «зуб бумаги», что у интерфейса, своей силы (`--m-grain`);
  в тёмной теме слабее (`--m-grain-dark`: сквозь провалы в белой бороде просвечивает тёмная бумага) и основа меха светлее.
  Контур — карандаш в три прохода:
  основная линия с разрывами (`stroke-dasharray`), более жирный нажим кусками (`m-pass2`) и тонкая линия рядом (`m-pass3`);
  плюс мягкая неровная кромка, как у линий интерфейса: два широких бледных ореола основной линии (`m-soft1`, `m-soft2`),
  каждый дрожит по-своему. Все доп. проходы — копии фигуры, которые добавляет сам компонент (`morePasses`, убирает за
  исчезнувшими фигурами). У штрихов заливки (`STROKES`) то же: тело и два ореола со своей волной.
  «Кипение» медленное (`BOIL_MS` 460 мс, 4 варианта по кругу, один общий таймер): `redraw()` сдвигает точки каждого
  пути (вариант зависит только от пути и номера кадра — копии контур/заливка совпадают), узоры штриховки меняют наклон
  и сдвиг, разрывы контура переезжают; глаза и рот не дрожат. Концы воротника на плечах скруглены.
  Не сделано: голос маскота в сообщениях бота; тема `midnight` пока не используется.
- **Как играть** — страница `/rules` (`pages/how-to.ts`, без входа): три шага, состояния шара, мандаринки (суммы из
  `/api/config`), друзья и фигуры за 1/3/5/10 друзей, честность/анонимность. Ссылка под отсчётом на главной.
  Просмотр отмечается в `localStorage['santa.rules.seen']` (`core/onboarding.ts`).
- **Установка** (`core/install.ts`, `components/install-card.ts`): с 2-го визита (на iPhone — с первого, ради уведомлений); Android/десктоп — системный диалог
  (`beforeinstallprompt`), iOS Safari — шаги «Поделиться → На экран „Домой“», в Telegram — ярлык Mini App
  (`addToHomeScreen`, Bot API 8.0). «Не сейчас» прячет на 10 дней.
- **Иней на листе** (`frost()` в handmade.ts, рисуется вместе с рамкой `.page`): перистые узоры из углов и снежинки
  по краям; все иголки собраны в три `<path>` по толщине (дёшево), обрезаны по листу. Цвет — токен `--frost`.

## Лавка (сделано, v1)

- Бэкенд `services/shop.py`: каталог в БД (`ShopItem`: key, category figure/lights/weather, rarity, price, set_key,
  friends_required, sort, active), `DEFAULT_CATALOG` только досевает недостающие строки при старте API (`seed_catalog`).
  `UserItem` — владение, **одна строка на копию**, и место фигуры `pad` 0..14 (None = не стоит). Фигуры можно покупать
  несколько раз (`MAX_COPIES` = 5, цена та же); огни, погода и подарки за друзей — по одной (проверяет код, не БД:
  уникальный ключ снят — на Postgres `ALTER`, локальный SQLite пересобирает таблицу в `db/core.py`).
- Покупка = `MandarinTx` с отрицательной суммой (`reason=purchase`, ref=ключ, у следующих копий `ключ#2`, `ключ#3`…),
  блокировка строки пользователя на Postgres.
  Наборы (`SET_BONUS`: yard +100, lights +150) — разовый бонус `set_bonus`. Подарки за друзей (1/3/5/10:
  candy-cane-green, sled-long, gingerbread, nutcracker) не продаются, выдаются сами (`ensure_milestones`).

- API: `GET /api/shop`, `POST /api/shop/buy {item}` (402 мало 🍊, 409 уже есть, 403 подарок, 404), `PUT /api/shop/place
  {item, pad|null, from_pad?}` (занятое место освобождается; `from_pad` — какая копия: стоящая на этом месте, без него —
  свободная копия); в ответе у товара `count`, `max`, `pads`; `/api/tree` отдаёт `decor` и `owned`.
- Фронт: `core/shop.ts` (`ShopState`: load/buy/place, тосты, эмодзи известных ключей), `components/tree/shop-sheet.ts`
  (вкладки, карточки, покупка в два нажатия, наборы). Смена вкладки — плоский свайп страниц влево-вправо, как экраны телефона (`animate.enter/leave`, без 3D),
  заштрихованная метка `.shop-tab-mark` переползает «змейкой» (передний край первым) и тянется к вкладке под мышью.
  Рисунки выступают за элементы на 18 px: `overflow-x: clip` на html и body, у листа `overflow-x: hidden` — иначе
  телефон расширяет страницу и лавка ездит вбок. Вход: 🛍 в шапке ёлки и кнопка в кошельке. Ключи: фигуры =
  `DECOR_KINDS` в scene.ts, гирлянды `lights-<skin>`, погода `snow-snowfall` (режим 2) / `snow-blizzard` (3).
  Купил фигуру → «Поставить во двор» → режим украшения → тап по стрелке (примерка) → «Поставить сюда» → `place`. Цены только из API.
- Картинки фигур в лавке — `web_app/public/shop/<key>.webp` (192 px, прозрачный фон), отрендерены из самих моделей:
  `window.santaTree.thumbnail(key)` (при `?debug`) возвращает data URL — снять Playwright'ом и сохранить. Новая фигура =
  добавить ключ в `PICTURES` (`core/shop.ts`) и картинку; без картинки показывается эмодзи. За картинкой свечение цвета редкости.
  Огни и погода пока с эмодзи.
- Камера уголка (`focusCorner`) смотрит сверху (dist 8.2, elev 0.85), чтобы ближняя фигура не закрывала остальные.
- Скриншоты лавки: скрипт с моками API лежал в scratchpad сессии (`shots.js`) — при необходимости написать заново по тому же принципу.

## Известные ограничения / не проверено

- Плавность 3D на реальных (особенно слабых) телефонах не проверена — только эмуляция (SwiftShader).
- Ogg-голосовые могут не играть в iOS Safari.
- Шары из бота (не из приложения) получают случайный стабильный цвет/узор.
- Контур ёлки/домика/шаров сделан другим способом, чем у моделей Kenney (нормали) — если будут «отстающие линии», смотреть `hull()` в scene.ts.

## Как проверять визуально

Собрать `npx ng build --output-path /tmp/...`, раздать статику с SPA-фолбэком (python http.server, 404 → index.html),
снять Playwright'ом (chromium предустановлен) с подменой `/api/**` моками и `localStorage['santa.session']='x'`.
Смотреть скриншоты самому перед отчётом. Не оставлять `web_app/dist` и `.angular` в репо.

## Качество кода (CI: `.github/workflows/ci.yml`)

- **Перед каждым коммитом:** `./scripts/check.sh --fix` — форматирует, автоисправляет и прогоняет всё то же, что CI.
  Коммитить только когда он зелёный. Без `--fix` — только проверка.
- Бэкенд (`bot/`, всё через `uv run --no-sync …`, зависимости `uv sync --group dev`):
  - форматирование и линт — **ruff** (`ruff format`, `ruff check --fix`); настройки в `bot/pyproject.toml` (строка 100);
  - типы — **ty** (`ty check`): новый код с аннотациями, без `Any` без нужды; подавлять только точечно
    `# ty: ignore[rule]` с причиной;
  - тесты — `pytest` (в CI ещё и на Postgres 17);
  - `requirements.txt` (из него ставит Docker) генерируется из `uv.lock`: после смены зависимостей
    `uv export --locked --no-dev --no-hashes --no-emit-project --no-header -o requirements.txt`.
- Фронт (`web_app/`):
  - форматирование — **`bun fmt`** (встроенный в bun ≥1.4, читает блок `prettier` в package.json и `.editorconfig`;

## Настройки «на глаз» и отладка

- `web_app/src/app/core/tuning.ts` (`TUNING`) — длительности и силы откликов, которые владелец подбирает сам:
  обводка кнопки (`scribbleMs`), перерисовка при наведении/нажатии, смена погоды (`weatherMs`), реакция объектов
  сцены (`sceneHover`/`scenePress`), перелистывание лавки и «змейка» вкладок. Новые такие числа — туда же.
- Отладочная панель 🐞 на ёлке: уровень праздника (ползунок, «настоящий») и мандаринки (задать/+500/0) на лету.
  Только админам: `DEBUG_TOOLS=1` на сервере (dev-tunnel.sh ставит по умолчанию) **и** Telegram ID в `WISH_VALIDATE_TG_IDS`
  (модераторы) или `ADMIN_TG_IDS`; остальным `PUT /api/debug` → 404, флаг `debug` приходит в `/api/me`. Уровень хранится в памяти API (`services/debug.py`), баланс — запись `reason=debug` в леджере.

## Формат коммитов

`<эмодзи> <тип>(<область>): <Описание>` — описание по-английски, с заглавной буквы, в повелительном наклонении,
без точки в конце, до ~72 символов. Область — необязательна, но желательна (`tree3d`, `api`, `bot`, `mailer`,
`shop`, `ci`, `deps`, `docs`…). Пример: `✨ feat(tree3d): Add new snowfall effect`.

| Эмодзи | Тип | Когда |
|---|---|---|
| ✨ | feat | новая возможность |
| 🐛 | fix | исправление бага |
| ♻️ | refactor | переделка без изменения поведения |
| ⚡️ | perf | производительность |
| 🎨 | style | форматирование, стиль кода |
| 💄 | ui | вид / вёрстка / визуал без новой механики |
| ✅ | test | тесты |
| 📝 | docs | документация, CLAUDE.md |
| 🔧 | chore | конфиги, скрипты, служебное |
| 👷 | ci | CI |
| ⬆️ | deps | обновление зависимостей |
| 🗃️ | db | схема БД / миграции |
| 🔥 | remove | удаление кода/файлов |

Тело коммита (по желанию) — что и зачем, через пустую строку после заголовка.

## Правила работы

- Коммитить и пушить в рабочую ветку; PR не создавать без просьбы.
- **История ветки — линейная** (решено с владельцем): без merge-коммитов. Если базовая ветка ушла вперёд — свои ещё
  не слитые коммиты переносить поверх неё (`rebase`), а не вливать базу в ветку. PR открывать в
  `claude/secret-santa-multiplatform-bnfqt3`, а не в `main`. Осторожно: `main` содержит копию старой истории с другими
  хешами (прошлый PR слит через rebase) — не вливать `main` в рабочие ветки, иначе в PR приедут десятки коммитов-дублей.
  Перед force-push — спросить владельца (только `--force-with-lease`, только свою ветку).
- Перед сдачей: `./scripts/check.sh --fix` (бэкенд-тесты, типы, линт, `ng build`), скриншоты изменённого.
- Тяжёлые независимые куски можно отдавать субагенту (владелец просил экономить лимиты; механика — Sonnet),
  разводя их по разным файлам.
